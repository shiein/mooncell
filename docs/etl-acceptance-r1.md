## 1. 阻断问题（必须先修，按顺序）

### R1-B1 CSV 步骤可在 Console 主机上任意读写文件

- **现象（已实测）**：普通用户只持有一个定义的 `edit` 授权：
  - 调 `POST /api/etl/pipelines/preview` 跑 `csv_input`，`path` 指向 `mooncell-etl.key`，能读出密钥内容；
  - 保存并运行 `csv_output`，能把文件写到数据目录以外。
  - 安装脚本生成的 systemd 服务没有 `User=`，Console 以 root 运行，所以这等于普通用户能以 root 任意写文件。
- **根因**：`steps/csv.go:121`、`:235` 直接用 `os.Open` / `os.OpenFile` 打开配置里的路径，没有任何目录约束。
- **要求**（已定方案）：
  - 新增配置 `[etl] file_root`，默认 `<数据库所在目录>/etl-files`，启动时自动创建，权限 0750。
  - `csv_input` / `csv_output` 的 `path` 一律按 `file_root` 下的相对路径解释。对管理员同样生效。
  - 以下情况在**编译期**报错，运行期再校验一次：绝对路径、含 `..` 越界、解析符号链接后（`filepath.EvalSymlinks`，对 output 校验父目录）落在根目录之外。
  - 改这个配置需要动 `consoleapp/config.go` 和 `app.go`（只限把配置透传给 ETL），本条已授权。
  - 前端表单的提示文字改为「相对 `file_root` 的路径」。
  - README 的数据集成章节和设计文档 §16 写明这条边界。
- **证伪测试**：
  - 绝对路径、`../`、指向根外的符号链接、根内到根外的符号链接目录，输入和输出各测一遍，都必须被拒；
  - 根内的合法相对路径能正常读写；
  - 在 `service_test.go` 层，以非管理员身份分别走预览和运行两条路径，都拿不到根外的文件内容，也写不出根外的文件。

### R1-B2 下推优化器静默改变结果

- **现象（已实测）**：同一条「表输入 → 过滤 → 表输出」链路，分别不下推（行内求值）和下推（SQL）各跑一遍，比较写入的行：

| 条件 | MySQL 8.4 | PG 16 |
|---|---|---|
| `name == "abc"`（数据含 `ABC`） | 下推后多出 `ABC`（MySQL 默认比较不区分大小写） | 一致 |
| `length(name) == 4`（数据含 `数据集成`） | 下推后丢了这行（MySQL 的 LENGTH 按字节算） | 一致 |
| `grp != 1`（grp 为 NULL） | 下推后丢了 NULL 行 | 下推后丢了 NULL 行 |
| `name == "a\\b"` | 下推后匹配不到（反斜杠被 MySQL 当成转义） | 一致 |
| `trim(name) == "x"`（值是 tab+x） | 下推后匹配不到 | 下推后匹配不到 |
| `name + "x" == "abcx"` | 下推后 6 行全命中（字符串被当数字算） | 下推后的 SQL 报错 |

  另外三点：`runs.go:303` 无条件开启下推，没有开关；预览不下推，所以预览结果和实际运行对不上；字符串字面量是拼进 SQL 的（`expr/sqlgen.go`），违反「禁止字符串拼接值」这条硬约束。
- **要求**（已定方案）：
  1. **默认关闭**：`pipeline.Settings` 新增 `pushdown bool`，缺省 `false`。只有定义显式开启时，运行路径才下推。设计器的「定义设置」里加开关，说明里写清楚「预览不下推，开启后运行结果以源库语义为准的部分已被排除」。旧定义的格式不变，缺省值即兼容。
  2. **字面量全部走绑定参数**：`ToSQL` 返回 `(sql, args)`，与表输入原 SQL 的参数一起按方言占位符顺序绑定（注意 `${}` 参数的序号衔接）。SQL 里不允许出现任何值字面量。
  3. **只下推能证明语义一致的子集**：
     - 字段类型（用编译期 schema）为整数、精确小数、浮点、日期、时间戳时，`==` `<` `<=` `>` `>=`、`in [...]`、`== nil` / `!= nil`、`&&` / `||` 可以下推。
     - `!=` 和 `not` 必须按引擎的 NULL 语义翻译（引擎里 `nil != 1` 为真），比如 `(a <> ? OR a IS NULL)`。做不到等价就拒绝下推。
     - 以下一律不下推：**字符串类型**的比较和 `in`；所有字符串函数（`length` `trim` `upper` `substr` `replace` 等）；`+` 和 `-` 两边有一边不是数值；`now()` / `today()`（数据库时钟、时区与引擎不同）；三元表达式。
  4. 「重编译失败就回退」保留，但回退要记一条 Warn 日志。
- **证伪测试**：
  - 新增 `etl_live` 差分测试：对白名单里每一种结构，加上上表这 6 个反例，在 PG、MySQL、达梦、Kingbase 上分别跑「不下推」和「下推」，断言写入的行集合完全一致。反例必须断言**不下推**。
  - sqlite 单测断言生成的 SQL 里不含值字面量。
  - 断言 `pushdown` 缺省时运行日志里没有下推条目。

### R1-B3 并行副本默认重复写入

- **现象（已实测）**：生成 10 行，表输出设 `copies=3`，结果写入 30 行，编译阶段没有任何警告。
- **根因**：分发方式默认是 `copy`（每个副本收全量）。而界面只在一个端口有多条连线时才显示分发选项（`Inspector.jsx:179`），单连线接到多副本节点时，用户没法选「分发」。设计文档只规定了「多条连线时默认 copy」，没有规定副本的分发方式。
- **要求**（已定方案）：
  - 把「多条连线之间怎么分」和「一条连线发给多个副本时怎么分」拆成两个独立语义。
  - 副本间默认**轮询分发**。节点上新增 `copiesDistribution: "distribute" | "copy"`，缺省为 `distribute`。
  - 检查器的「并行副本」旁边加这个选项。
  - 设计文档 §4 写清两者的区别。
  - 以下情况编译期给 Warning：
    - `copies>1` 的 `insert_update` / `update` / `delete` / `sync_after_merge` / `db_lookup`：多个副本并发按键写时，没有唯一约束会产生竞态和重复；
    - `copies>1` 节点的下游存在要求有序输入的步骤（`unique_sorted`、`merge_rows` 等）。
- **证伪测试**：
  - 生成 N 行，表输出设 3 个副本、缺省分发，写入行数等于 N，且没有重复；
  - 显式设为 `copy` 时写入 3N 行；
  - 上面两种 Warning 各有用例；
  - 已有的 `TestNodeCopies` 按新语义更新。

### R1-M3 非管理员的运行记录可能显示为空
- `api.go:897` 的 `listRuns`，以及 `overview` 里的近期运行，都是先按 `Limit` 取数据、再按授权过滤。其他定义跑得频繁时，非管理员看到的是空列表或残缺列表。
- 改为在 SQL 里按授权的定义 ID 过滤（参数化的 `IN`，或者 JOIN `etl_grants`），再 `LIMIT`，游标分页语义保持不变。
- 证伪测试：200 条他人定义的运行加 1 条自己定义的运行，非管理员第一页必须能看到自己那条。

### R1-M4 表输出退化逐行写入时不区分错误类型
- 现在批量失败的原因哪怕是连接断开、超时、`context` 取消，也会退化成逐行写入，把行全部转到错误输出，而步骤显示成功。
- 只有**数据类错误**才退化逐行，例如违反约束、类型或长度错误；需要按方言识别 SQLSTATE 或错误码。基础设施错误直接让整步失败。
- 逐行阶段如果连续 N 行（比如 100 行）都是非数据类错误，也要整步失败。
- 证伪测试：
  - 用 sqlite 让中途连接失效（关闭 DB 句柄，或用注入错误的 Querier），步骤必须失败，错误输出行数为 0；
  - 唯一约束冲突仍走原来的退化逻辑。

### R1-M5 复制含通知凭据的作业后，凭据会失效
- 这一条是验收时代码推断，没有跑过，请先写测试确认。
- `duplicateDefinition` 原样拷贝了 notify 的 `secretCipher` 和 `aadSuffix`。副本第一次保存时，`sealDocSecrets` 会把 `aadSuffix` 改成副本自己的 ID，但密文是按原定义 ID 加密的，运行时会解密失败。
- 修复方向：复制时按新 ID 解密后重新加密，跟导入路径保持一致。
- 另外，运行时开密应当由运行中的定义 ID 推导 AAD，不能信任文档里的 `aadSuffix`；需要兼容的话，至少校验它和当前定义 ID 一致。
- 证伪测试：复制 → 保存副本 → 运行，通知请求头里带有正确凭据；原样的 `aadSuffix` 被篡改成别的定义 ID 时，开密失败。
